# UniApp 合并转发设计

## 背景

当前 `im-uniapp-ui` 已支持单条消息转发，但聊天页没有消息多选、逐条转发、批量删除和合并转发能力。参考工程 `im-kit-vue-ui-h5` 已实现完整链路，并使用 IM Store 提供的合并消息序列化协议生成 type `101` 自定义消息。

当前 UniApp 工程内置的 Store 已提供以下能力：

- `serializeMergeMsgs`
- `deserializeMergeMsgs`
- `isChatMergedForwardMsg`

因此本次不复制或修改 Store 底层协议，主要在 UniApp UI 层补齐跨端交互、校验、文件上传、消息发送、卡片展示和聊天记录查看器。

## 目标

1. 覆盖当前 UniApp 工程支持的 App、H5、微信小程序和鸿蒙运行环境。
2. 聊天页支持长按进入多选，并提供“合并转发”“逐条转发”“删除”三个操作。
3. 严格对齐 `im-kit-vue-ui-h5` 的 type `101` 合并转发协议和消息类型规则。
4. 支持合并转发消息卡片、会话摘要、只读聊天记录详情和最多三层嵌套。
5. 保持现有单条转发、收藏转发和标记消息转发行为兼容。
6. 为新增纯逻辑和发送流程建立独立、可执行的自动化测试与定向类型检查。

## 非目标

- 不修改 NIM SDK 或内置 Store 的合并转发协议实现。
- 不清理本功能以外的历史页面、类型错误或重复代码。
- 不增加多目标会话转发。
- 不持久化正在进行的多选、转发或聊天记录查看任务。
- 不保证转发消息和独立留言具备服务端事务原子性。

## 参考基准

最终行为和协议以同仓库 `im-kit-vue-ui-h5` 的最新合并转发实现为准，而不是用户最初给出的旧目录 `im-kit-vue-ui`。重点参考：

- `Chat/message/merged-forward/utils.ts`
- `Chat/message/merged-forward/card.vue`
- `Chat/message/merged-forward/modal.vue`
- `Chat/message/message-multi-select/utils.ts`
- `Chat/message/message-forward.vue`
- `Chat/index.vue`

UniApp 端遵循现有页面、`uni.*` API、条件编译和组件风格，不直接移植浏览器 DOM、`fetch` 或全屏弹层实现，也不假设所有运行时都提供浏览器 `File`。

## 总体架构

### 聊天页持有多选状态

`pages/Chat/index.vue` 是多选状态的唯一持有者，负责：

- `isMultiSelecting`：是否处于多选模式。
- `selectedMessageKeys`：已选消息稳定键集合。
- `selectedMessages`：从当前源消息列表按显示顺序派生的消息数组。
- 进入、切换、取消多选。
- 发起合并转发、逐条转发和批量删除。
- 多选期间隐藏输入区并展示底部操作栏。

消息选择状态通过以下组件链传递：

```text
Chat/index.vue
  -> message-list.vue
    -> message-item.vue
      -> message-bubble.vue
```

`message-item.vue` 负责选择框、选中样式和点击切换。`message-bubble.vue` 的长按操作菜单新增“多选”，触发后默认选中当前消息。处于多选模式时，不再触发普通消息点击、回复、单条转发等操作。

### 多选与校验工具

新增 `utils/messageMultiSelect.ts`，集中维护：

- 稳定选择键生成。
- 可选消息判断。
- 逐条转发、合并转发和删除数量限制。
- 消息发送状态检查。
- 消息类型白名单。
- 合并转发嵌套深度判断。
- 批量删除后会话最后消息同步。

组件不重复实现消息类型规则，避免不同入口出现不一致判断。

### 转发任务

现有 `pages/Chat/forward.vue` 扩展为三种模式：

```ts
type ForwardMode = "single" | "oneByOne" | "merged"
```

新增内存级 `forwardTask` 模块，在聊天页和目标选择页之间保存：

- 任务 ID。
- 转发模式。
- 源会话 ID。
- 已选消息稳定键。
- 创建时间。

每次只保留一个活动转发任务，任务有效期为 10 分钟。路由只传任务 ID 和目标会话类型，不传消息对象或大量消息 ID，也不把消息写入本地持久化存储。页面刷新、进程重启或任务过期后，目标选择页展示失败提示并返回聊天页。

目标选择页完成发送后通过带任务 ID 的全局事件通知原聊天页清理多选状态；取消或失败不发送成功事件。聊天页卸载、创建新任务或收到匹配的成功事件时清理旧任务，避免跨会话误消费。

现有单条转发、收藏转发和标记转发继续兼容当前查询参数；多选任务走新的任务 ID 路径。

### 合并转发协议工具

新增 `utils/mergedForward.ts`，职责包括：

- type `101` payload 解析和严格校验。
- 合并消息识别和嵌套深度读取。
- 消息摘要生成。
- 来源会话信息生成。
- UTF-8 文本 MD5 计算。
- 跨端上传源生成和临时文件清理。
- 合并消息上传、构造和发送。
- 下载文本标准化和反序列化。

该模块通过参数接收 Store 和 NIM 实例，纯解析和判断函数不直接依赖组件实例，便于单元测试。

### 卡片与详情页

新增合并转发卡片组件，在聊天消息列表中识别合法合并消息并展示：

- 标题：`来源会话名称 + 的消息`。
- 最多三条摘要。
- 固定页脚“聊天记录”。

点击卡片后下载并解析合并内容，创建内存级查看任务，再跳转到独立全屏详情页。详情页只接收查看任务 ID，并只读复用消息组件。嵌套卡片沿用同一任务和页面机制。

详情页使用页面路由而不是 H5 的 DOM 全屏弹层，以适配 App、小程序和鸿蒙的导航与返回行为。

## 多选交互

### 进入和退出

- 用户在可选择消息的长按菜单中点击“多选”后进入多选模式，并默认选中该消息。
- 导航栏显示已选数量，并提供“取消”。
- 系统返回键在多选状态下优先退出多选，不直接离开聊天页。
- 时间分割线、撤回提示和通知消息不展示选择框。
- 进入多选后收到的新业务消息可正常展示和选择。

### 操作栏

底部从左到右展示：

1. 合并转发
2. 逐条转发
3. 删除

未选择消息时三个操作均为禁用状态。操作栏使用固定高度和稳定布局，不因文字长度或禁用状态引发布局跳动。

### 目标选择

- 合并转发和逐条转发复用现有好友/群组目标选择页。
- 每次只选择一个目标会话。
- 取消目标选择或关闭发送确认弹窗后返回聊天页，并保留多选状态。
- 发送成功后清理任务和多选状态。
- 发送失败后保留任务和多选状态，允许重试。

## 消息规则

### 数量限制

| 操作 | 最大数量 |
| --- | ---: |
| 逐条转发 | 10 |
| 合并转发 | 100 |
| 批量删除 | 50 |

### 可选择消息

真实业务消息可以被选择，包括语音、话单和发送失败消息。以下内容不可选择：

- 时间分割线。
- 撤回提示。
- 通知消息。
- 缺少客户端消息 ID 的临时展示项。

发送失败等不可转发消息仍可被选择并用于批量删除。

### 逐条转发白名单

- 文本。
- 图片。
- 视频。
- 文件。
- 可识别的合并转发自定义消息。

消息还必须发送成功、未撤回、没有失败状态且不是通知消息。

### 合并转发白名单

- 文本。
- 图片。
- 视频。
- 文件。
- 语音。
- 话单。
- 可识别且当前深度小于 3 的合并转发自定义消息。

以下消息不可合并转发：

- 发送失败消息。
- 已撤回消息。
- 通知消息。
- 未知或当前端无法解析的消息。
- 非合并转发的自定义消息。
- 深度大于或等于 3 的合并转发消息。

### 不可转发消息处理

用户点击转发时先检查数量限制，再计算不可转发消息。存在不可转发项时展示“异常说明”确认弹窗：

- 取消：保持当前选择，不进入目标选择。
- 确认：从本次转发集合和当前已选集合中移除不可转发项。
- 移除后没有可转发消息：展示本地化提示并停留在多选模式。
- 仍有可转发消息：继续进入目标选择。

## 合并转发协议

### 序列化

发送前按源消息列表顺序整理消息，并调用：

```ts
store.msgStore.serializeMergeMsgs(messages, {
  appVersion,
  sdkVersion,
})
```

Store 会写入每条消息的发送者昵称和头像。为避免 P2P 备注名进入合并记录，序列化调用在一个无异步让出的同步 `try/finally` 块内临时将昵称解析切换为用户真实昵称，并确保无论成功或异常都立即恢复原函数。

### 摘要

摘要取排序后的前 3 条消息，每条包含：

```ts
interface MergedForwardAbstract {
  senderNick: string
  content: string
  userAccId: string
}
```

- P2P 来源会话和发送者使用用户资料真实昵称，不使用好友备注。
- 群聊来源会话使用群名称。
- 语音摘要为 `[语音]`。
- 话单摘要区分语音通话和视频通话。
- 嵌套合并转发摘要为 `[聊天记录]`。
- 其他类型复用现有消息摘要函数。

### 文件与上传

序列化内容保存为 UTF-8 文本并计算 MD5。跨端上传源适配顺序为：

1. 运行时支持 `File` 时创建文本 `File`。
2. 小程序或提供文件系统管理器的运行时写入临时文本路径。
3. App 运行时使用可用的本地文件系统写入临时路径。

上传统一调用：

```ts
store.storageStore.uploadFileActive(fileOrPath)
```

非 `File` 临时文件在上传完成或失败后通过 `finally` 清理。MD5 使用纯 TypeScript UTF-8 编码实现，不依赖 `TextEncoder`、Node `crypto` 或浏览器专用 API。

### 自定义消息

最终 payload 严格保持为：

```ts
interface MergedForwardPayload {
  type: 101
  data: {
    abstracts: MergedForwardAbstract[]
    depth: number
    md5: string
    sessionId: string
    sessionName: string
    url: string
  }
}
```

使用 NIM 创建文本为 `[聊天记录]` 的自定义消息，并通过 `sendMessageActive` 发送。用户留言作为独立文本消息发送，不写入 payload。

留言和合并消息并行发起，以保持与 H5 基准一致。任一消息成功后都应由 Store 正常保留在本地消息列表；整体 Promise 失败只影响结果反馈，不回滚已经发送成功的消息。

### 嵌套深度

- 普通消息生成的第一层合并消息深度为 1。
- 包含合并消息时，新深度为已有最大深度加 1。
- 深度大于或等于 3 的合并消息不能继续被合并。
- 合法合并消息仍可单条转发和逐条转发。

## 接收与查看

### 识别

接收端先使用 `isChatMergedForwardMsg`，再校验以下字段：

- 消息类型为自定义消息。
- payload `type` 为 `101`。
- `data.url` 为非空字符串。
- `data.md5`、`data.abstracts`、`data.depth` 和来源字段类型合法。

payload 从 `attachment.raw`、兼容字段 `content` 和 `text` 中解析。无法通过校验的自定义消息沿用现有未知消息降级展示，不渲染聊天记录卡片。

### 下载与校验

点击卡片后使用 `uni.request` 以文本形式下载 `data.url`：

1. 下载失败时提示“获取聊天记录失败”。
2. MD5 不匹配时停止解析并提示失败。
3. 对历史移动端数据中字段 `12` 的数字/字符串差异做标准化。
4. 调用 `deserializeMergeMsgs`。
5. 反序列化结果为空时提示失败，不打开空详情页。

成功结果只保存在内存查看任务中。重复点击同一卡片时复用当前页面生命周期内的解析结果，避免重复下载。

### 详情页只读行为

详情页复用消息展示，但明确禁用：

- 回复、转发、删除、标记、收藏和多选。
- 头像跳转。
- 已读回执。
- @ 提及交互。
- 输入区和新消息订阅。

保留：

- 文本复制。
- 图片预览。
- 视频预览。
- 文件打开或下载。
- 嵌套聊天记录打开。
- 原消息时间、发送者昵称和左右布局。

语音消息在详情中只展示 `[语音消息]`，不创建播放器。话单只展示通话类型摘要，不触发通话能力。

## 其他展示入口

合法合并转发消息在以下位置统一展示 `[聊天记录]`：

- 会话列表最后一条消息。
- 单行消息预览组件。
- 回复引用摘要。
- 收藏列表。
- 标记列表。

合并转发卡片本身支持现有合法操作，包括单条转发、收藏、标记、删除和通过“多选”进入批量操作。

## 批量删除

批量删除前检查 50 条限制并展示二次确认。确认后一次调用：

```ts
store.msgStore.deleteMsgActive(selectedMessages)
```

成功后退出多选并同步当前云端或本地会话对象的最后一条消息。失败时保留多选状态和选择集合，并展示失败提示。

## 错误与状态恢复

| 场景 | 行为 |
| --- | --- |
| 断网发起转发 | 提示网络异常，保留多选状态 |
| 超过数量限制 | 提示对应限制，不进入目标选择 |
| 存在不可转发消息 | 确认移除后继续，取消则原样保留 |
| 转发任务丢失或过期 | 提示获取转发消息失败并返回聊天页 |
| 临时文件生成失败 | 提示合并转发失败，保留选择 |
| 文件上传失败 | 清理临时文件，提示失败，保留选择 |
| 合并消息发送失败 | 保留选择，允许重试 |
| 留言成功但合并消息失败 | 留言保留，提示合并转发失败 |
| 下载、MD5 或反序列化失败 | 提示获取聊天记录失败，不打开详情 |
| 批量删除失败 | 保留选择并提示失败 |

所有新增可见文案同时补齐中文和英文语言包。

## 测试设计

### 单元测试

新增轻量测试入口，覆盖：

- 稳定选择键优先级和回退规则。
- 可选、逐条转发、合并转发白名单。
- 10/100/50 条数量限制。
- 合并 payload 的多来源解析和严格校验。
- 嵌套深度计算和深度 3 拦截。
- UTF-8 MD5，包括中文、英文和 emoji 输入。
- 字段 `12` 数字到字符串的兼容标准化。
- 转发任务和查看任务的创建、读取、消费、过期和清理。

### 发送流程测试

使用 Mock Store、NIM 和文件适配器验证：

- 消息按源顺序传入 Store 序列化。
- 昵称解析在异常时也通过 `finally` 恢复。
- 上传参数为 `File` 或本地路径。
- 临时文件在成功和失败后都被清理。
- type `101` payload 字段完整。
- 留言和合并消息分别发送。
- 部分成功时不回滚成功消息。
- 下载失败、MD5 不匹配和空反序列化结果被正确拒绝。

### 定向类型检查

项目现有全量 `vue-tsc` 存在 113 个历史错误。本功能新增独立类型检查配置，只包含新增文件、修改文件及必要声明，使本功能可以作为独立门禁运行。该门禁不能替代全项目类型治理，也不能声称全量类型检查已经通过。

### 平台验收矩阵

在 App、H5、微信小程序和鸿蒙分别验证：

1. 长按进入多选、默认选中、动态选择和返回退出。
2. 合并转发、逐条转发和批量删除的禁用态、限制和确认。
3. 好友和群组目标选择、留言、成功和失败状态恢复。
4. 同端及跨端发送、接收和 `[聊天记录]` 会话预览。
5. 卡片标题、摘要、长昵称省略和详情页显示。
6. 图片、视频、语音、文件、话单和嵌套合并消息。
7. 不可转发消息移除、深度限制、断网和上传失败重试。
8. 回复、收藏和标记入口中的 `[聊天记录]` 展示。

## 验收标准

1. 四类目标运行环境均能完成多选、三种批量操作和详情查看。
2. 与 `im-kit-vue-ui-h5` 互发的 type `101` 消息能够双向识别和查看。
3. 合并转发限制、白名单、摘要、真实昵称和三层嵌套规则一致。
4. 合法合并消息在聊天、会话、回复、收藏和标记入口均正确展示。
5. 失败不会无提示退出多选，也不会留下未清理的本地临时文件。
6. 新增单元测试、发送流程测试和定向类型检查通过。
7. 不引入本功能以外的行为变化，不宣称解决项目现有全量类型错误。
